# 2026-08-07 添加填充结果反馈机制

## 需求

自动填充完成后，用户需要知道：填了什么、没填什么、为什么没填。需要三层反馈：
1. 页面右下角浮动通知条（自动消失）
2. Popup 中可查看的详细报告
3. 填充结果按模块分组 + 未填充原因细分 + 行动建议

## 变动状态机

| 阶段 | 状态 |
|------|------|
| 原始 | 填充完成后仅在 Popup 显示"X 已填充 · Y 待检查"，无页面内反馈，无字段级明细 |
| 操作 | 新增填充结果类型系统 + 引擎内填充日志 + 页面浮动通知 + Popup 详细报告 |
| 当前 | 填充后页面右下角弹出浮动通知（8s 自动消失），Popup 显示"查看上次填充结果"按钮，支持按模块查看、按状态分类、行动建议 |

## 变更文件

### 新增

- `lib/fillResult.ts` — 填充结果类型定义 + 模块映射 + 信号→规范字段名映射 + 构建函数

### 修改

- `entrypoints/content/engine.ts` — 
  - `fillCurrentForm()` 改为返回 `FillResult` 类型
  - `fillPass()` 新增 `entries: FillEntry[]` 参数，填充时逐字段记录状态
  - 每字段记录：label、canonicalField、value、status、reason、module、suggestion
  - 填充完成后通过 `chrome.storage.session.set` 缓存结果

- `entrypoints/content/index.tsx` —
  - `AUTOFILL_CURRENT_FORM` 处理器：填充后调用 `injectFillNotification()` 注入浮动通知
  - 新增 `injectFillNotification()` 函数：创建底部浮动通知条，含填充率、按模块统计、全部字段展开、8秒自动消失

- `entrypoints/popup/main.tsx` —
  - 新增 `lastResult` 状态，启动时从 `chrome.storage.session` 读取缓存
  - 自动填充后更新 `lastResult`
  - 新增"查看上次填充结果"按钮，点击展示详细报告（含填充率、模块统计、待处理字段）

- `使用手册.md` — 新增第 14 节"填充结果反馈"，含页面浮动通知展示、状态分类表、Popup 查看方式、技术说明

## 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 结果来源 | fill-time 日志（引擎记录），非反向扒 DOM | 引擎自己知道做了什么，更可靠；select/radio/checkbox 等关键字段通过 `applyFill` 返回值验证 |
| 投递渠道 | 页面内浮动通知 + Popup 查阅 | 页面内立刻感知，Popup 可深究细节，两处互补 |
| 持久化 | `chrome.storage.session`，key=tabId | 关闭 tab/浏览器自动清除，无淘汰策略问题，无版本管理，零维护成本 |
| 信息展示 | 分层折叠：填充率 → 模块统计 → 全部字段 | 避免信息过载，ADHD 友好，一眼看到关键信息 |
| 未填充原因 | 细分 7 种（no_data/no_match/legal_skip/custom_component/fill_error/partial/skipped） | 让用户知道"为什么没填"和"怎么解决" |
