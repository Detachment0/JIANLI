## 1. 快速启动

```bash
npm install     # 安装依赖
npm run dev     # 启动开发模式（热重载）
```

在 Edge/Chrome 加载扩展：
- 打开 `edge://extensions` 或 `chrome://extensions`
- 开启"开发者模式"
- 点击"加载已解压的扩展"
- 选择项目目录下的 `.output/chrome-mv3-dev/` 文件夹

**验证安装成功**：访问任意页面，右下角出现 `JT` 按钮 → 点开弹出侧面板。

## 2. 设置 OpenAI API 密钥

> 只有需要 AI 功能时才需要配置。纯自动填充无需 API 密钥。

**操作**：右键扩展图标 → 点击"跟踪仪表盘" → 设置 → 填入 API Key。

**正常 case**：填入有效密钥后，AI 功能（智能添加、答案草拟、AI 粘贴跟踪）立即可用。

**异常 case**：密钥无效或过期 → 各 AI 按钮会返回错误提示，不会崩溃。

**边界 case**：密钥为空时，AI 按钮会提示"请先添加 API 密钥"，不会静默失败。

## 3. 一键注入简历

> 最快的方式：把简历文本交给开发者，生成 `RESUME_PROFILE` 后，在 Popup 点击按钮即可注入。

**操作**：点击扩展图标 → 弹出窗口底部 → 点击"注入简历"。

**正常 case**：点击后提示"简历已注入，可开始自动填充。" → 打开任意求职表单 → 点击"自动填充当前页面" → 姓名、技能、经验等字段自动填充。

**异常 case**：点击后无反应 → 检查扩展是否已重新加载（`npm run dev` 后刷新扩展）。

**边界 case**：重复注入 → 新的简历数据覆盖旧的，始终使用最新版本。

**清除简历**：点击"清除简历" → 清空之前注入的简历数据 → 下次自动填充时 Profile 为空。

**位置**：Popup 底部，与核心功能按钮用分隔线隔开。

## 4. 个人资料管理

### 4.1 手动填写

**位置**：仪表盘 → 个人资料 或 侧面板 → 资料

填写内容自动保存（修改后 550ms 自动存入 `chrome.storage.local`）。

**支持字段**：
- 身份信息（姓名、邮箱、电话、地址、LinkedIn/GitHub）
- 工作授权（美国授权、签证状态、英语水平）
- 申请默认值（推荐来源、期望薪资、可见性）
- 人口统计（可选，留空则每次填充时审查）
- 技能、经验、个人项目

### 4.2 智能添加

**操作**：在"智能添加"文本框粘贴项目笔记、简历文本、个人简介等 → 点击"使用 AI 添加"。

**正常 case**：
```
输入：  "5年React经验，主导过设计系统重构，在Google工作过。"
结果：  技能自动添加 React(5年)，经验添加"设计系统重构"条目。
```

**异常 case**：AI 返回空或格式错误 → 个人资料不变，显示错误提示。

**边界 case**：输入包含非英语文本 → AI 尝试理解并映射到对应字段。

### 5.3 导入简历 PDF

**操作**：点击"导入简历 PDF" → 选择 PDF 文件 → AI 解析并填充个人资料。

**正常 case**：PDF 上传后，姓名、技能、经验等字段自动填充。

**异常 case**：PDF 无法读取 → 提示"无法读取简历 PDF"。

**边界 case**：重复导入 → 覆盖已有字段，未覆盖的字段保留。

## 5. 自动填充申请表单

### 5.1 操作方式

| 方式 | 操作 |
|------|------|
| 弹出窗口 | 点击扩展图标 → 点击"自动填充当前页面" |
| 侧面板 | 打开侧面板 → 点击"自动填表" → "自动填充此页面" |

### 5.2 填充策略（三层优先级）

1. **Profile 确定性匹配** → 字段名直接匹配（如 `firstName` → 名）
2. **记忆答案模糊匹配** → 之前记住的问题-答案对
3. **AI（预订）** → 目前未启用，前两层优先

### 5.3 填充结果反馈

填充完成后弹窗报告：
- 已填充数量
- 待检查项（模糊匹配、法律确认字段、人口统计字段）

**正常 case**：Greenhouse/Lever/LinkedIn/Indeed 等标准表单 → 邮箱、姓名、电话等字段自动填充。

**异常 case**：表单无输入框或字段无法识别 → 返回 0 填充，所有字段标记为"缺少"。

**边界 case**：法律确认字段（如"我同意条款"）→ 标记为 `confirmation`，永不自动填充，要求用户手动操作。

**边界 case**：在扩展自己的 Options 页面点击自动填充 → 提示"当前页面不支持此功能"。

### 5.5 中文字段映射字典

**问题**：滴滴招聘、Boss 直聘等中文网站，表单标签是中文，引擎默认只认英文关键词。

**解决**：仪表盘 → 设置 → "中文字段映射字典"。

| 操作 | 说明 |
|------|------|
| 修改 | 下拉选择目标字段，输入同义词（逗号分隔） |
| 添加 | 点击"添加映射"按钮 |
| 删除 | 点击行尾的 X 按钮 |
| 恢复默认 | 删除所有条目后，下次打开会自动重置为默认列表 |

**默认已预填** 19 条常见映射（姓名、邮箱、电话、公司、职位、期望薪资等）。

**示例**：如果某网站用"公司名称"而不是"公司"，你可以去字典里给 `currentEmployer` 添加一条 `公司名称`。

## 6. 技能匹配评分

### 6.1 词库匹配（自动）

**触发条件**：访问 LinkedIn/Indeed 等职位详情页 → 侧面板自动显示匹配分数。

**正常 case**：职位描述含"React, TypeScript, PostgreSQL" → 匹配你资料中的技能 → 显示分数（如 70/100）。

**结果解读**：
- ≥70：绿色按钮（高匹配）
- 40-69：黄色按钮（中匹配）
- <40：红色按钮（低匹配）

**交互**：点击缺少的技能标签 → 自动添加到你的个人资料技能列表。

### 6.2 AI 深度分析（可选）

**操作**：侧面板 → 匹配标签 → 点击"深度分析（AI）"。

**正常 case**：返回 AI 匹配分数、优势、差距、推荐投递角度。

**异常 case**：AI 调用失败 → 显示错误，不影响词库匹配结果。

**边界 case**：职位描述加载超时（10秒）→ 提示"无法读取此页面的职位描述"。

## 7. AI 答案草拟

### 7.1 从侧面板草拟

**操作**：侧面板 → 答案 → 粘贴问题 → 点击"草拟答案"。

**正常 case**：
```
问题： "Why do you want to work here?"
结果：  AI 根据你的个人资料生成回答，可编辑后复制或保存。
```

**保存到记忆**：草拟后点击"保存答案" → 存入答案库，下次自动填充可复用。

**异常 case**：AI 返回空 → 显示错误提示。

### 7.2 管理答案库

**位置**：仪表盘 → 答案

**操作**：手动添加问题-答案对、编辑已有答案、删除。

**正常 case**：添加后自动填充时匹配到相同问题 → 直接填充保存的答案。

**边界 case**：添加相同问题 → 提示"另一个答案已使用该问题"，拒绝重复。

## 8. 申请跟踪器

### 8.1 添加跟踪记录

**三种方式**：

| 方式 | 操作 | 适用场景 |
|------|------|----------|
| 手动添加 | 仪表盘/侧面板 → 填写公司、职位信息 | 已知职位信息时 |
| AI 粘贴 | 粘贴职位文本 → 自动解析公司、职位、薪酬 | 有职位描述文本时 |
| 提交后提示 | 提交申请时自动弹出确认框 | 在支持的 ATS 上提交时 |

**状态流转**：`Saved → Applied → Screen → Interview → Offer → Rejected / Ghosted`

### 8.2 看板管理

**拖拽操作**：在看板视图中拖拽卡片到不同状态列 → 状态自动更新。

**正常 case**：拖拽"Applied"列卡片到"Interview"列 → 状态更新，数据持久化。

**边栏筛选**：可切换显示哪些状态列（核心/全部），搜索关键词过滤。

### 8.3 跟进管理

**设置跟进日期**：展开卡片 → 设置"跟进日期" → 按钮显示待办数量。

**正常 case**：设置跟进日期为今天 → 顶部显示"待办"计数，提醒跟进。

**边界 case**：跟进日期过期超过 60 天 → 不再计入待办计数。

### 8.4 CSV 导出

**操作**：跟踪器 → 点击导出图标 → 下载 CSV 文件。

**边界 case**：导出前检查 CSV 内容是否包含敏感信息（如答案文本）。

## 9. 侧面板（Widget）

### 9.1 打开方式

| 方式 | 操作 |
|------|------|
| 浮动按钮 | 点击页面右下角 `JT` 按钮 |
| 弹出窗口 | 点击扩展图标 → "打开侧面板" |

| 标签 | 显示条件 | 功能 |

| 匹配 | 进入职位详情页 | 技能匹配评分 + AI 深度分析 |

**正常 case**：在支持的 ATS 提交申请 → 侧面板自动弹出确认框 → 可保存为"已申请"或忽略。

**异常 case**：提交检测失败 → 可在侧面板手动点击"跟踪此职位"。

## 10. Upwork 提案跟踪

### 10.1 跟踪提案

**操作**：在 Upwork 提案页面 → 打开侧面板 → Upwork 标签 → 自动读取提案金额和 Connects → 点击"跟踪提案"。

**正常 case**：自动读取合同类型、出价金额、基础 Connects → 保存到跟踪器。

**自动重试**：如果页面加载慢，侧面板会每 500ms 重试读取，最多 5 秒。

### 10.2 提案状态管理

**状态流转**：`Submitted → Responded → Interviewed → Offered → Hired → Rejected → Withdrawn`

**操作**：在侧面板或仪表盘中选择提案状态 → 自动记录状态变更时间。

### 10.3 Upwork 统计

**位置**：仪表盘 → 跟踪器 → 显示 Upwork 汇总统计：
- 提案总数、已消耗 Connects、回复率、面试率、Offer 数、录用数

## 11. 演示模式

**开启**：仪表盘 → 设置 → 点击"开始演示模式"。

**演示模式行为**：
- 所有写操作跳过（saveProfile、db.applications.add 等）
- 数据使用 `DEMO_PROFILE` + `createDemoApplications()` + `createDemoMemories()`
- 仪表盘显示紫色"演示模式"徽章
- 侧面板显示"演示模式"提示

**正常 case**：开启演示模式 → 看到 7 条示例申请记录和 4 条示例答案，可随意操作而不影响真实数据。

**退出**：点击"退出演示模式" → 恢复真实数据。

**边界 case**：演示模式下修改个人资料 → 提示"演示模式变更是临时的"，退出后不保存。

## 12. 常见问题与边界情况

### 12.1 扩展无法打开/闪退

| 现象 | 原因 | 解决 |
|------|------|------|
| 点击扩展图标无反应 | 构建问题 | 重新运行 `npm run dev` 并在扩展管理页面刷新 |
| 点击扩展图标窗口闪退 | 构建中存在重复插件 | 确保 `wxt.config.ts` 的 `vite.plugins` 中没有 `@vitejs/plugin-react` |

### 12.2 自动填充/侧面板报错

| 错误信息 | 原因 | 解决 |
|----------|------|------|
| "Cannot access contents of url" | 当前在扩展自身页面（如 Options） | 切换到求职网站页面再操作 |
| "Receiving end does not exist" | 页面未加载 Content Script | 刷新页面后重试 |
| 自动填充无反应 | 页面不是标准表单 | 确认当前页面是求职申请表单 |

### 12.3 数据相关

| 场景 | 行为 |
|------|------|
| 个人资料修改后未保存 | 关闭仪表盘前等待 1 秒，有自动保存延迟 |
| 申请记录在跟踪器中未见 | 检查状态筛选是否隐藏了该状态 |
| 答案库中已保存的答案未自动填充 | 确保问题文本完全匹配，或使用模糊匹配（通过记忆检索） |
| CSV 导出包含敏感信息 | 导出前手动审查，答案文本可能包含个人信息 |

### 12.4 AI 相关

| 场景 | 行为 |
|------|------|
| API 密钥无效 | 各 AI 按钮返回错误提示 |
| AI 响应超时 | 等待 30 秒后返回超时错误 |
| AI 返回内容不准确 | 编辑后保存，不依赖 AI 完全正确 |
| 没有 API 密钥 | 纯自动填充和跟踪功能完全可用，仅 AI 功能不可用 |

### 12.5 性能与兼容性

| 场景 | 说明 |
|------|------|
| SPA 页面导航（LinkedIn/Indeed） | 侧面板每 1 秒检测 URL 变化，自动更新匹配分析 |
| 多个标签页 | 申请记录变更通过 `applicationsRev` 计数器同步，所有标签页自动刷新 |
| 浏览器更新 | 扩展数据存储在 `chrome.storage.local` 和 IndexedDB 中，浏览器更新不丢失数据 |

## 13. 离线测试

| 📋 实习经历 | 多段，含公司、部门、职位、职责、成果 | 10/段 |

| 🔬 科研/论文/专利 | 多段，科研+论文+专利合并为一个可添加块 | 14/段 |

| ✍️ 个人陈述 | 自我评价、职业规划、个人成就、兴趣爱好 | 4 |
| 👨‍👩‍👧 家庭/利益冲突 | 多段家庭成员 + 亲属任职声明 | 8/段 |
| 📌 招聘信息 | 内推、来源、历史申请、历史任职 | 8 |
| 🛂 工作资格 | 工作授权、签证、海外经历 | 5 |
| 📝 应聘问卷 | 开放题 + 筛选问题 | 6 |
| 📎 附件 | 中文简历、英文简历、其他附件 | 3 |
| ⚖️ 授权/声明 | 隐私政策、数据授权、人才库、背景调查、电子签名 | 7 |

### 13.3 测试步骤

1. 打开测试页面 `http://localhost:8080/test-form.html`
2. 确保已注入简历（点击扩展图标 → "注入简历"）
3. 点击扩展图标 → "自动填充当前页面"
4. 观察表单字段是否被填入

### 13.4 多段测试（重点）

## 15. 预览填充

### 15.1 功能说明

在填充之前，**先预览再执行**，防止填错信息。

| 操作 | 行为 |
|------|------|
| 预览填充 | 引擎检测表单字段 → 匹配数据 → 生成预览报告 → 弹窗展示 |
| 确认填充 | 用户确认后执行实际填充 |
| 取消 | 不做任何修改 |

### 15.2 操作步骤

1. 点击扩展图标 → 点击"预览填充"
2. 页面弹出预览弹窗，展示：
   - 填充率估算
   - 按模块统计（基本信息 3/3、联系方式 2/2 等）
   - 全部字段清单（可展开）
3. 预览弹窗中点击"确认填充" → 执行实际填充 → 弹出结果通知
4. 或点击"取消" → 不做任何修改
