## 文档与代码一致性验证

### 已确认的一致性

- `npm run compile`（tsc --noEmit）通过，TypeScript 类型无错误
- `package.json` 中的 5 个 scripts（dev/build/zip/compile/postinstall）均已验证
- `lib/schema.ts` 的 `ExtensionMessage` 联合类型包含 22 种消息，与消息协议文档一致
- `lib/db.ts` 的 Dexie schema（applications + answerMemory 两表）与数据模型文档一致
- `lib/storage.ts` 的 6 个 storage key 与文档一致
- `lib/synonyms.ts` 的 37 个 CanonicalField 与文档一致

### 发现的架构偏差（已在文档中标注）

1. **AI 调用路径偏差**：
   - AGENTS.md 原始 Global Invariant #2 声称"Background 是唯一 AI 调用入口"
   - 实际代码中 Options 仪表盘（`entrypoints/options/main.tsx`）直接 `import` 并调用 `lib/ai.ts` 中的函数（`importProfileFromCv`、`draftApplicationFromJobPosting`、`enrichProfileFromText`、`draftSingleAnswer`）
   - **已修正**：AGENTS.md Global Invariant #2 已更新为"AI 调用有两条路径"的准确描述
   - 该偏差在 `architecture/containers.md` 和 `architecture/flows/ai-integration.md` 中也有标注

2. **两套本地字段匹配逻辑**：
   - `entrypoints/content/engine.ts` 的 `directProfileFill()` 使用 `domSignal()` + `ancestorSignal()` 提取信号，confidence=0.98
   - `lib/mapping.ts` 的 `deterministicValue()` 使用 `SYNONYMS` 同义词表匹配，confidence=0.94
   - 两者信号提取方式不同，但都映射到 Profile 字段。已在 `architecture/flows/autofill.md` 中明确区分。

### 仍然无法确定的信息

- `enabledSites` 设置项（greenhouse/lever/ashby/linkedin）在代码中未见被读取使用，可能为预留功能
- `TRACK_CURRENT_APPLICATION` 消息类型在 schema 中定义但 Background 返回错误，Content Script 的 `queueTrackCurrentApplication()` 直接使用 `APPLICATION_SUBMITTED` 消息

## 变更协议遵守

本次变更为纯文档创建，不涉及代码修改，无需运行 `npm run compile` 验证代码（但已验证当前代码编译通过）。

后续修改代码的 AI 应遵循 AGENTS.md 中的 Change Protocol：
1. 阅读 AGENTS.md
2. 确定影响的文档范围
3. 读取相关文档
4. 验证文档与代码一致性
5. 实施代码修改
6. 运行 `npm run compile` + `npm run dev`
7. 同步更新受影响的文档
8. 在变动文件夹中记录变更
