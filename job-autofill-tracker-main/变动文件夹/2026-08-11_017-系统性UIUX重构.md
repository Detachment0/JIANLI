## 变更概述

在保留所有底层业务能力和数据逻辑的前提下，对 Chrome 求职助手进行全面的 UI/UX 重构。核心理念：将产品从"求职管理后台"重新定位为 **Context-aware Job Application Copilot**（上下文感知的求职申请副驾驶），遵循"最小注意力占用 × 最大任务推进能力"原则。

## 变更事项

### 1. 建立统一 Design System

| 状态机 | 说明 |
|--------|------|
| **原来** | Popup、Widget、Dashboard 三个 Surface 使用彼此独立的视觉语言，颜色、间距、字体、圆角等无统一规范 |
| **操作** | 创建共享 Design Tokens 和 Primitives |
| **现在** | 三个 Surface 共享同一套 Design System，通过 CSS 变量实现全局一致性 |

**修改文件**：
- `lib/design-tokens.css` — **新建**。定义全局设计变量：Color（Light/Dark 双主题）、Typography hierarchy、Spacing scale（0-10）、Radius、Elevation（Surface 0-2）、Motion（120-350ms）、Z-index、Border width
- `lib/primitives.css` — **新建**。提供可复用基础组件样式：Button（primary/ghost/danger）、Input、Select、Badge（accent/success/warning/danger）、Surface、Divider、SegmentedControl
- `entrypoints/content/index.tsx` — 导入 design-tokens.css 和 primitives.css

## 架构原则

### Surface 职责边界
- **Popup**：快速入口 / 当前状态 — 回答"当前页面助手能做什么？"
- **Widget**：核心产品 / 当前申请副驾驶 — 回答"帮我完成眼前这个职位申请"
- **Dashboard**：长期求职管理 — 回答"我的整个求职过程现在怎么样？"

### 颜色语义
- Neutral (gray) = 常规内容
- Accent (blue) = 当前重点/品牌
- Success (green) = 已成功完成
- Warning (amber) = 需要用户介入
- Danger (red) = 错误/危险操作

### Surface 空间模型
- Surface 0 = 招聘网站
- Surface 1 = Assistant（Widget/Popup/Dashboard 默认层级）
- Surface 2 = Modal/Preview
- 临时反馈层 = Toast/Transient feedback

### Motion 原则
- 微交互：120–200ms
- Surface transition：200–320ms
- 优先 transform + opacity
- 避免 layout jank
- 支持 prefers-reduced-motion
