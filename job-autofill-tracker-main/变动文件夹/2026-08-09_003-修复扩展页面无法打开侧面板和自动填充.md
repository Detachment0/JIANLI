# 修复扩展页面无法打开侧面板和自动填充

## 时间
2026-08-07

## 变更说明

### 问题
当用户在 Options 页面（仪表盘）打开 Popup 并点击"打开侧面板"或"自动填充当前页面"时，Background Service Worker 尝试通过 `chrome.scripting.executeScript` 向当前标签页注入 Content Script，但 Options 页面是 `chrome-extension://` 协议的 URL，不在 `host_permissions` 范围内，导致注入被拒绝并抛出错误：
```
Cannot access contents of url "chrome-extension://.../options.html". Extension manifest must request permission to access this host.
```

### 修改

#### 文件：`entrypoints/background.ts`

| 状态 | 说明 |
|------|------|
| 原状态 | `sendMessageToTabWithInjection` 在 `chrome.tabs.sendMessage` 失败后，直接调用 `chrome.scripting.executeScript` 注入 Content Script，未处理 `chrome-extension://` 协议 URL 的权限拒绝错误。 |
| 操作 | 在 `chrome.scripting.executeScript` 外层添加 try-catch，捕获 `Cannot access contents of url` 错误并转换为用户友好的中文提示。 |
| 当前状态 | 当活动标签页为扩展自身页面时，返回清晰的中文错误消息"当前页面不支持此功能（扩展自身页面无法使用侧面板或自动填充）。" |

### 判断无需更新文档的原因
本次修改仅增强了 `sendMessageToTabWithInjection` 函数的错误处理，将底层权限拒绝错误转换为用户友好的中文提示。未改变：
- 架构边界（Container 间关系不变）
- 模块职责（background.ts 职责不变）
- 业务链路（autofill 和 widget 的触发流程不变）
- 消息协议（消息类型不变）
- 数据结构（Schema 不变）
- 全局不变量（Invariants 不变）
- 运行方式（开发/构建命令不变）
